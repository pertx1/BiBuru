BiBuru · Guía completa

Todo lo que tienes que hacer tú, paso a paso, desde cero hasta tener BiBuru funcionando en tu ordenador y en tu iPhone, con avisos, IA y YouTube. Tiempo estimado: 2–3 horas (puedes parar entre secciones). Coste: 0 € (la IA tiene tope de 10 €/mes y solo se usa si pones la clave).
Cómo leer esta guía. Cada paso dice dónde entrar, qué pulsar, qué copiar y dónde pegarlo. Lo que va en este formato es un botón o menú que ves en pantalla. Lo que va en este otro es texto que copias o escribes tal cual. Las webs cambian de diseño de vez en cuando: si un botón se llama algo parecido pero no idéntico, es ese. Si algo no coincide en absoluto, hazme una captura y dime en qué paso estás.
Importante: qué está comprobado y qué no. He probado la app entera en un entorno local (base de datos real, navegador real, avisos descifrados, IA y YouTube simulados). No he podido probarla contra tu Supabase, tu Vercel, tu iPhone, la API real de Gemini ni la de YouTube/TikTok, porque no tengo acceso a tus cuentas. Los nombres de botones de Supabase, Vercel y Google Cloud están escritos de memoria: pueden variar un poco. Al final hay una sección «Si algo falla».

0 · Antes de empezar

  • Un ordenador con Chrome y un iPhone con Safari (iOS 16.4 o superior para los avisos).
  • Acceso a tu correo oiier.gsss@gmail.com (recibirás códigos).
  • Tu cuenta de GitHub (pertx1).
  • Un bloc de notas al que llamaremos «mi bloc», donde pegarás datos que iremos recogiendo. Lo guardas tú; no se lo mandes a nadie, ni a mí.
Nada de esto pide tarjeta. Supabase, Vercel, GitHub, Google AI Studio y Google Cloud (para YouTube) se usan en su capa gratuita. Si alguna pantalla te pide una tarjeta o te ofrece «Upgrade», cancela y avísame. La única API de pago potencial es Gemini: sin clave no gasta nada y, con clave, la app para al llegar a tu tope mensual.
Regla de oro de seguridad. Hay claves que van solo a Vercel (variables de entorno) y nunca a un chat, correo o captura: la contraseña de la base de datos, la clave secret / service_role de Supabase, GEMINI_API_KEY, GOOGLE_CLIENT_SECRET y las claves generadas en el paso 8. Si crees que se ha filtrado una, se cambia (la sección 13 explica cómo).

1 · Llevar el código a la rama principal de GitHub

Ahora mismo el código está en una rama de trabajo. Vercel despliega desde main, así que hay que fusionarlas.

  1. Dime en el chat: «crea la PR». Yo abro una Pull Request (propuesta de fusión) y te doy el enlace.
  2. Abre el enlace e inicia sesión en GitHub si te lo pide.
  3. Baja hasta el recuadro verde/gris y pulsa Merge pull request, luego Confirm merge.
  4. Comprueba: https://github.com/pertx1/BiBuru muestra carpetas src, supabase, docs. En la pestaña Actions, un ✔ verde es bueno; una ✘ roja, dímelo.

2 · Crear la base de datos en Supabase

2.1 Crear la cuenta

  1. Entra en https://supabase.com y pulsa Start your project (arriba a la derecha).
  2. Pulsa Continue with GitHub y autoriza. Así no necesitas otra contraseña.
  3. Si te pide crear una Organization: nombre Personal, tipo Personal, plan Free. Pulsa Create organization.

2.2 Crear el proyecto

  1. Pulsa New project.
  2. Name: biburu.
  3. Database Password: pulsa Generate a password. Cópiala a «mi bloc» bajo el título «Contraseña BD Supabase». No la necesitarás ahora, pero si la pierdes se puede restablecer.
  4. Region: elige West EU (Ireland) o Central EU (Frankfurt). Cualquiera de Europa; más cerca = más rápido.
  5. Si aparece un Pricing plan / Compute, deja Free (0 $/mes).
  6. Pulsa Create new project y espera 1–2 minutos hasta que desaparezca la rueda de carga.
Dato: los proyectos gratuitos de Supabase se pausan si pasan 7 días sin ningún uso. Con el uso diario de la app (y el cron de la Fase 5) no ocurrirá. Si algún día ves «Project paused», entra y pulsa Restore project.

2.3 Copiar la URL y la clave pública

  1. En el menú izquierdo, abajo del todo, pulsa el engranaje Project Settings.
  2. Pulsa API Keys (en algunas versiones: API o Data API).
  3. Busca la Project URL (algo como https://abcdefghijk.supabase.co). Cópiala a «mi bloc» como SUPABASE_URL. Si no la ves en esa pantalla, está en Project Settings → Data API o en General.
  4. En API Keys busca la clave Publishable key (empieza por sb_publishable_…). Pulsa el icono de copiar y pégala en «mi bloc» como PUBLISHABLE_KEY.
    Si tu pantalla solo muestra la pestaña Legacy API Keys, copia la clave anon / public (empieza por eyJ…) y anótala como ANON_KEY. También sirve.
NO copies la clave llamada secret (sb_secret_…) ni service_role. Son las llaves maestras. No las necesitas ahora.

3 · Crear las tablas (aplicar las 11 migraciones, en orden)

Una «migración» es un archivo con instrucciones SQL que crea tablas y reglas de seguridad. Son 11 archivos y hay que ejecutarlos en este orden, una sola vez cada uno.

Repite estos pasos para cada archivo, empezando por el 1:

  1. En GitHub abre https://github.com/pertx1/BiBuru/blob/main/supabase/migrations/NOMBRE-DEL-ARCHIVO.sql (cambia el nombre).
  2. Pulsa el icono Copy raw file (dos cuadraditos, arriba a la derecha del código).
  3. En Supabase, menú izquierdo: SQL Editor → + New query.
  4. Pega (Ctrl+V / Cmd+V) y pulsa el botón verde Run.
  5. Abajo debe poner «Success. No rows returned». Marca el archivo como hecho en esta lista y pasa al siguiente.
Si un archivo da error: no sigas con los siguientes. Haz una captura del error (texto rojo) y mándamela diciendo el número de archivo. No ejecutes dos veces un archivo que salió bien: daría «already exists» (inofensivo, pero lía).
El archivo 6 intenta activar las extensiones pg_cron y pg_net. Si Supabase te las pide activar a mano: Database → Extensions, busca cada una y pulsa el interruptor. Después vuelve a ejecutar solo el bloque de la función configure_cron (lo haré yo si hace falta: dímelo).

Comprobación: Table Editor debe listar, entre otras: profiles, businesses, orders, expenses, tasks, notes, inbox_items, saved_videos, integrations. Y Storage debe mostrar un bucket privado llamado receipts.

4 · Configurar el acceso por correo

4.1 Permitir crear cuenta con contraseña (sin código del correo)

  1. Authentication (icono de persona, menú izquierdo) → Sign In / Providers (puede llamarse Providers o Settings).
  2. Activa Allow new users to sign up (en algunas versiones está en User Signups).
  3. En Email: Enable Email provider ON y Confirm email OFF (apagado). Así la cuenta se crea al instante, sin código ni enlace. Si ves Email OTP Length, déjalo en 6 (se sigue usando para el acceso «Código por correo»).
  4. Pulsa Save.
Quién puede crear cuenta. Cualquier persona: BiBuru viene con el registro abierto y cada cuenta tiene su propio espacio, aislado del resto. Cuidado con la IA: todas las cuentas usan tu clave de Gemini, y cada una tiene su propio tope mensual (10 € por defecto). Si no quieres ese riesgo, no pongas GEMINI_API_KEY, o añade en Vercel OPEN_SIGNUP = false (y tu correo en ALLOWED_EMAILS) para cerrar el registro y redesplegar.
Crea tu cuenta tú primero. Como ya no se verifica el correo, quien se registre antes con un correo se queda con él. Crea la tuya (paso 7.1) nada más desplegar, antes de compartir la dirección con nadie.

4.2 Poner el correo bonito (con enlace y código)

  1. Authentication → Email Templates (puede estar dentro de Emails).
  2. Elige la plantilla Magic Link.
  3. Subject: borra lo que haya y escribe Tu acceso a BiBuru.
  4. Message body (modo Source): borra todo y pega el contenido del archivo supabase/templates/magic-link.html del repositorio (en GitHub ábrelo y pulsa Copy raw file).
  5. Pulsa Save.
¿Por qué un código además del enlace? En el iPhone, la app instalada y Safari son «mundos separados». Si pulsas el enlace del correo se abre Safari, no la app. Con el código de 6 dígitos entras directamente dentro de la app instalada.

4.3 Tu usuario

Ya no hace falta crearlo a mano en Supabase: lo creas tú desde la pantalla de la app en el paso 7 (Crear cuenta). Después comprueba en Table Editor → profiles que hay 1 fila y en workspaces otra llamada «Personal».

5 · Publicar la web en Vercel

5.1 Cuenta

  1. Entra en https://vercel.com/signup.
  2. Elige Hobby (gratis, uso personal). Pon tu nombre.
  3. Pulsa Continue with GitHub y autoriza.

5.2 Importar el proyecto

  1. Pulsa Add New… → Project.
  2. En Import Git Repository, si no ves BiBuru, pulsa Adjust GitHub App Permissions y da acceso al repositorio BiBuru (Only select repositories → BiBuru → Save). Vuelve a Vercel.
  3. Junto a pertx1/BiBuru pulsa Import.
  4. Framework Preset debe decir Next.js. No toques el resto (Root Directory vacío, Build Command por defecto).

5.3 Variables de entorno

En Environment Variables añade estas tres, una a una (nombre en Key, valor en Value, Add). Las demás se añaden en los pasos 8, 9 y 10.

Key (nombre exacto)Value (qué pegar)

NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEYLa PUBLISHABLE_KEY (sb_publishable_…). Si solo tienes la antigua, usa en su lugar el nombre NEXT_PUBLIC_SUPABASE_ANON_KEY con la clave eyJ….

  1. Pulsa Deploy. Espera 1–3 minutos hasta ver «Congratulations!».
  2. En el panel verás tu dirección bajo Domains (parecida a biburu-xxxx.vercel.app). Cópiala a «mi bloc» como TU_URL (con https://).

6 · Decirle a Supabase tu dirección

5.4 Decirle a Supabase cuál es tu dirección

  1. Supabase → Authentication → URL Configuration.
  2. Site URL: pega TU_URL (por ejemplo https://biburu-xxxx.vercel.app), sin barra final.
  3. Redirect URLs → Add URL: pega https://biburu-xxxx.vercel.app/** (tu URL con /** al final).
  4. Pulsa Save changes.
Importante: el botón del correo usa la «Site URL». Si la dejas en localhost el enlace no funcionará.

8 · Activar avisos y tareas programadas (cron)

Esto hace que lleguen los avisos de tareas, el resumen de la mañana, y que la IA y YouTube trabajen en segundo plano aunque la app esté cerrada y el móvil bloqueado.

8.1 Generar las claves (sin instalar nada)

  1. En BiBuru abre Ajustes → Asistente de configuración y pulsa Generar claves.
  2. Aparecen cuatro claves: NEXT_PUBLIC_VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, CRON_SECRET y TOKEN_ENCRYPTION_KEY. Cópialas a «mi bloc» con el botón de copiar de cada una. No se guardan en ningún sitio: si cierras la pantalla sin copiarlas, genera otras.

8.2 Clave secreta de Supabase

  1. Supabase → Project Settings → API Keys.
  2. Copia la clave secret (sb_secret_…) —o, en Legacy API Keys, la service_role— a «mi bloc» como SERVICE_KEY. Es la llave maestra: solo a Vercel.

8.3 Pegarlas en Vercel

  1. Vercel → tu proyecto → Settings → Environment Variables. Añade (todas en All Environments):
KeyValue
NEXT_PUBLIC_VAPID_PUBLIC_KEYla del asistente
VAPID_PRIVATE_KEYla del asistente
VAPID_SUBJECTmailto:oiier.gsss@gmail.com
CRON_SECRETla del asistente
SUPABASE_SERVICE_ROLE_KEYSERVICE_KEY de «mi bloc»
TOKEN_ENCRYPTION_KEYla del asistente (la usará YouTube, paso 10)
  1. Deployments → los tres puntos del último despliegue → Redeploy (sin marcar «use existing build cache» si te lo pregunta). Las variables nuevas solo valen tras redesplegar.
Después de redesplegar, vuelve a entrar en BiBuru si te pide sesión. No vuelvas a generar claves con el asistente salvo que quieras sustituirlas en Vercel.

8.4 Programar el cron en Supabase

  1. Supabase → SQL Editor → + New query y pega esto cambiando TU_URL (con https://, sin barra final) y TU_CRON_SECRET (el CRON_SECRET de tu bloc): 
    select public.configure_cron('TU_URL', 'TU_CRON_SECRET');
  2. Run. Debe responder: Programado: avisos (1 min), IA (2 min), análisis de vídeos (3 min) y sincronización de YouTube (cada 6 h).
  3. Si da error por cron o net: Database → Extensions, activa pg_cron y pg_net y repite.
  4. Para ver que corre: Database → Cron (o select * from cron.job_run_details order by start_time desc limit 5;). Debe haber filas con «succeeded».
Plan B (si Supabase Cron no te va): en https://cron-job.org (gratis) crea 4 tareas con la cabecera Authorization: Bearer TU_CRON_SECRET a: TU_URL/api/cron/reminders (cada minuto), /api/cron/ai (cada 2 min), /api/cron/videos (cada 3 min) y /api/cron/youtube-sync (cada 6 h).

8.5 Activar los avisos en el iPhone

  1. Abre BiBuru desde el icono de la pantalla de inicio (los avisos en iPhone solo funcionan con la app instalada).
  2. Ajustes → Avisos en este dispositivo → Activar avisos en este dispositivo. Acepta el permiso.
  3. Pulsa Enviar aviso de prueba: debe llegarte «BiBuru · aviso de prueba» aunque bloquees el móvil.
  4. Prueba real: crea una tarea para dentro de 10 minutos con hora, cierra la app y bloquea el móvil. Debe avisarte a la hora elegida (por defecto 30 min antes para eventos y a su hora para tareas; ajustable en Qué avisos quieres).
Los avisos llegan con un retraso de hasta ~1 minuto (el cron es por minutos). Si no llega nada: sección 14.

9 · Activar la IA (Gemini)

La IA clasifica lo que apuntas, responde en el chat, dicta por voz y resume vídeos. Es opcional: sin clave, BiBuru funciona igual (la captura se clasifica a mano).

  1. Entra en https://aistudio.google.com con tu cuenta de Google.
  2. Pulsa Get API key (menú izquierdo o arriba) → Create API key. Si te pide elegir proyecto, Create API key in new project.
  3. Copia la clave (AIza…) a «mi bloc» como GEMINI_KEY.
  4. Vercel → Environment Variables: añade GEMINI_API_KEY = GEMINI_KEY. Opcionales (no los pongas si no sabes): GEMINI_MODEL_FAST (por defecto gemini-3.5-flash-lite), GEMINI_MODEL_VIDEO (por defecto gemini-3.8-flash), AI_MAX_RPM (peticiones por minuto, por defecto 10).
  5. Redeploy (como en 8.3).
  6. BiBuru → Ajustes → Inteligencia artificial: debe decir «Clave de Gemini configurada en el servidor ✔». Comprueba el presupuesto mensual (10 € por defecto) y los precios por millón de tokens.
Importante sobre costes. Los precios que trae BiBuru son estimaciones mías, no los oficiales. Entra en https://ai.google.dev/pricing, mira el precio vigente de tus dos modelos (entrada y salida, € o $ por millón de tokens) y corrígelos en Ajustes → Inteligencia artificial → Precios. Si los precios que pones son más altos que los reales, el tope salta antes (lado seguro). Si el nombre de un modelo ha cambiado, cámbialo con las variables GEMINI_MODEL_*.
Qué hace el tope: al 80 % te llega un aviso; al 100 % la IA se pausa hasta el mes siguiente (o hasta que subas el presupuesto). La captura rápida nunca se bloquea. Además, los vídeos de más de 20 minutos no se analizan solos: te enseñan el coste estimado y tú decides.

Pruebas

  • Captura «Comprar etiquetas mañana a las 9» con el botón +; en Bandeja aparece una propuesta «Tarea» con Aceptar, Corregir, Descartar.
  • Captura «Gasto de 42,50 euros en etiquetas»: la propuesta pide Confirmar; un gasto nunca se crea solo.
  • Asistente: pregunta «¿Qué tareas tengo mañana?».
  • Micrófono del panel de captura: pulsa, habla, pulsa de nuevo; el texto aparece (iPhone: acepta el permiso del micrófono).

10 · Conectar YouTube (Google Cloud)

Trae tus «Me gusta» y listas de YouTube a Favoritos y los resume. BiBuru solo pide permiso de lectura. Es opcional: sin esto puedes pegar enlaces a mano en Favoritos.

Límites que debes conocer: (1) La lista «Ver más tarde» no se puede importar: Google no la ofrece a ninguna aplicación. Pasa esos vídeos a una lista normal o pega los enlaces. (2) TikTok no tiene API de lectura pública: se guarda por enlace y se analiza solo con título/autor, sin ver el vídeo. (3) En modo «pruebas», Google caduca el acceso a los 7 días; el paso 10.6 lo evita.

10.1 Crear el proyecto

  1. Entra en https://console.cloud.google.com con tu cuenta de Google. Acepta los términos si te los pide (no te pedirá tarjeta para esto).
  2. Arriba, junto al logo, pulsa el selector de proyecto → Proyecto nuevo. Nombre: BiBuru → Crear. Selecciona el proyecto cuando termine.

10.2 Activar la API de YouTube

  1. Menú (☰) → APIs y servicios → Biblioteca.
  2. Busca YouTube Data API v3 → ábrela → Habilitar.

10.3 Pantalla de consentimiento

  1. APIs y servicios → Pantalla de consentimiento de OAuth (puede llamarse Google Auth Platform). Pulsa Comenzar.
  2. Nombre de la aplicación: BiBuru. Correo de asistencia: el tuyo. Siguiente.
  3. Público: Externo. Siguiente. Correo de contacto: el tuyo. Acepta la política → Crear.
  4. En Público (o «Usuarios de prueba») pulsa Add users y añade oiier.gsss@gmail.com → Guardar.
  5. En Acceso a los datos (Scopes) → Añadir o quitar permisos → busca y marca .../auth/youtube.readonly → Actualizar → Guardar.

10.4 Crear las credenciales

  1. Credenciales → + Crear credenciales → ID de cliente de OAuth (o Clientes → Crear cliente).
  2. Tipo de aplicación: Aplicación web. Nombre: BiBuru web.
  3. En URI de redirección autorizados → + Añadir URI: pega TU_URL/api/google/callback (por ejemplo https://biburu-xxxx.vercel.app/api/google/callback; exactamente así, sin barra final).
  4. Crear. Aparecen ID de cliente y Secreto del cliente: cópialos a «mi bloc» como GOOGLE_ID y GOOGLE_SECRET.

10.5 Pegar en Vercel y conectar

  1. Vercel → Environment Variables: GOOGLE_CLIENT_ID = GOOGLE_ID y GOOGLE_CLIENT_SECRET = GOOGLE_SECRET. (TOKEN_ENCRYPTION_KEY ya la pusiste en 8.3.) Redeploy.
  2. BiBuru → Ajustes → YouTube y vídeos → Conectar con Google.
  3. Google avisará de que «la app no está verificada»: es normal (eres tú). Pulsa Configuración avanzada → Ir a BiBuru (no seguro) y acepta el permiso de ver tu cuenta de YouTube.
  4. Vuelves a Ajustes con «Cuenta de Google conectada ✔». Pulsa Elegir listas…, marca las que quieras y luego Sincronizar ahora.

10.6 Que no caduque a los 7 días

  1. Google Cloud → Pantalla de consentimiento → Público → Publicar la aplicación (Pasar a producción). Para un uso personal con un solo usuario Google puede mostrar el aviso de «no verificada»; no hace falta verificarla. Si no publicas, tendrás que pulsar «Conectar con Google» de nuevo cada semana.

Pruebas

  • En Favoritos pega un enlace de YouTube: aparece guardado y, en 1–3 minutos, con resumen, puntos clave, categoría y utilidad.
  • Pega un enlace de TikTok: se guarda con su título y la ficha indica que se analizó solo con texto.
  • Un vídeo de más de 20 min aparece como «Vídeo largo: confirma el análisis» con coste estimado y dos botones.
  • Pega el mismo enlace dos veces: dice «ya estaba guardado» (sin duplicados).
  • Capturar un enlace de YouTube desde el botón + y aceptarlo en la Bandeja lo manda a Favoritos.

11 · Importar tus datos de PROFITY

El importador es un programa que se ejecuta una vez, en un ordenador con Node. Para no instalar nada, usa GitHub Codespaces (un ordenador en el navegador, gratis hasta 120 horas de núcleo al mes para cuentas personales; si te pidiera tarjeta, no sigas y avísame).

11.1 Conseguir la cadena de conexión de PROFITY

  1. Entra en el panel de la base de datos de PROFITY (Neon: https://console.neon.tech) → tu proyecto → Dashboard → Connection string.
  2. Copia la cadena (empieza por postgresql://) a «mi bloc» como PROFITY_DB. Si hay un selector, elige la rama principal y el rol por defecto.

11.2 Abrir Codespaces

  1. En https://github.com/pertx1/BiBuru pulsa el botón verde <> Code → pestaña Codespaces → Create codespace on main. Espera 1–2 minutos: se abre un editor tipo VS Code en el navegador.
  2. Abajo hay una zona negra llamada Terminal. Escribe npm install y pulsa Intro. Espera a que termine.
  3. Crea el archivo de claves: escribe cp .env.example .env.local + Intro, y ábrelo con un clic en .env.local en la lista de archivos de la izquierda.
  4. Rellena solo estas tres líneas (sin comillas ni espacios):
    PROFITY_DATABASE_URL=PROFITY_DB de tu bloc
NEXT_PUBLIC_SUPABASE_URL=SUPABASE_URL de tu bloc
SUPABASE_SERVICE_ROLE_KEY=SERVICE_KEY de tu bloc
    Guarda con Ctrl+S.

11.3 Simular y luego importar

  1. Simulación (no escribe nada): 
    npm run import:profity:dry
    Te cuenta cuántos registros hay y los totales de ingresos, gastos y pedidos.
  2. Si los números te cuadran con lo que ves en PROFITY: 
    npm run import:profity -- --email oiier.gsss@gmail.com
    Te muestra el resumen y pide confirmar. Al final dice «Todo coincide. Importación completada.» (compara los totales origen/destino). Si dice «NO coincide», no sigas y mándame la salida.
  3. Se puede repetir sin duplicar. Por defecto, tus ventas van a Akerra y lo de Vinted a un negocio Vinted (opciones --business, --vinted-business, --no-vinted).
Al terminar, borra el Codespace (https://github.com/codespaces → los tres puntos → Delete): contiene tu clave secreta de Supabase. Esa clave nunca se sube al repositorio (.env.local está ignorado por git).

Comprobación: en BiBuru → Negocios aparecen Akerra y Vinted con sus pedidos, gastos e ingresos y las estadísticas coinciden con las de PROFITY. Mientras dudes, no apagues PROFITY.

13 · Uso diario, copias de seguridad y costes

Copias de seguridad

  • Descarga tus datos en Ajustes → Tus datos → Todo (JSON) cada mes (guárdalo en tu nube). Los CSV se abren en Excel.
  • Los tickets (fotos/PDF) están en Supabase → Storage → receipts; el JSON conserva sus rutas.
  • El plan gratuito de Supabase no incluye copias automáticas descargables: la exportación mensual es tu seguro.

Límites gratuitos que conviene saber

ServicioLímite relevanteQué hacer
Supabase Free500 MB de base de datos, 1 GB de archivos, pausa tras 7 días sin actividad.El cron y el uso diario evitan la pausa. Si ves «Project paused»: Restore project.
Vercel HobbyUso personal no comercial; funciones de hasta 60 s.Si en el futuro vendes la app a terceros, hay que pasar a un plan de pago (te avisaré).
GeminiDe pago por uso; tope propio de 10 €/mes en BiBuru.Revisa Ajustes → Inteligencia artificial una vez al mes. En AI Studio puedes ver el uso real.
YouTube API10.000 unidades/día (sincronizar cuesta ~1 por cada 50 vídeos).Sin acción.

Cambiar o perder una clave

  • Supabase secret/service_role: Supabase → API Keys → regenerar; pégala en Vercel (SUPABASE_SERVICE_ROLE_KEY) y redeploy.
  • CRON_SECRET: nueva en el asistente → Vercel → redeploy → vuelve a ejecutar el select public.configure_cron(...) del paso 8.4 con la nueva.
  • VAPID: si cambias estas claves, hay que volver a activar los avisos en cada dispositivo.
  • TOKEN_ENCRYPTION_KEY: si la cambias, hay que desconectar y volver a conectar YouTube (el acceso guardado ya no se podría descifrar).
  • GEMINI_API_KEY / GOOGLE_CLIENT_SECRET: regenerar en su consola y actualizar en Vercel + redeploy.

Si un día quieres salirte

Ajustes → Tus datos → Borrar mi cuenta y todos mis datos (pide escribir tu correo; borra tickets, datos y accesos; es irreversible). Descarga antes el JSON.

Abrir BiBuru a más personas

Hoy el registro está cerrado en tres capas. Para más gente: activar «Allow new users to sign up» en Supabase, poner shouldCreateUser: true en la acción de login y sustituir ALLOWED_EMAILS por una tabla de invitaciones. Los espacios compartidos ya están preparados en la base de datos (falta la pantalla de invitaciones). Pídemelo cuando quieras.

14 · Si algo falla

SíntomaCausa probable → qué hacer
El despliegue de Vercel falla en «Build»Falta o está mal escrita una variable. Revisa los nombres del paso 5.3 y vuelve a desplegar. Si sigue, copia el final del registro rojo y mándamelo.
«Redirect to /login» en bucle o «perfil»La migración 1 no se ejecutó entera o el usuario se creó antes de ella. Mira Table Editor → profiles: debe tener 1 fila. Si está vacía, bórralo en Authentication → Users, comprueba la migración 1 y créalo otra vez.
«Supabase todavía pide confirmar el correo» al crear la cuentaFalta desactivar Confirm email (paso 4.1). Si la cuenta ya se creó a medias: Authentication → Users → ⋯ → Confirm user (o bórrala) y repite.
El correo no llega (acceso por código)Mira Spam. El SMTP gratuito de Supabase es lento y limitado (pocos correos por hora): espera unos minutos y no pidas muchos seguidos. Comprueba que el usuario existe y «Site URL» es tu dirección.
El enlace del correo abre localhost o da error«Site URL» y «Redirect URLs» mal puestas (paso 6). En el iPhone, usa el código en lugar del enlace.
«Invalid API key» / pantalla en blanco tras entrarURL o clave de Supabase mal pegadas en Vercel (espacios, falta algún carácter). Corrige y redeploy.
Los avisos no lleganComprueba en orden: (1) app instalada en la pantalla de inicio del iPhone; (2) «Enviar aviso de prueba» funciona; si no → variables VAPID y redeploy; (3) select * from cron.job_run_details order by start_time desc limit 5; con «succeeded»; si «failed», el CRON_SECRET de configure_cron no coincide con el de Vercel; (4) horas de silencio en Ajustes.
La IA dice «no está configurada»Falta GEMINI_API_KEY o no redesplegaste.
Error de IA con «404 / model not found»El nombre del modelo cambió: pon uno vigente en GEMINI_MODEL_FAST / GEMINI_MODEL_VIDEO (los ves en AI Studio) y redeploy.
Las capturas se quedan «pendientes de IA»Presupuesto agotado, límite por minuto o el cron de IA sin programar (paso 8.4). Se reintentan solas; o pulsa «Reintentar» en la tarjeta.
Google: «Error 400: redirect_uri_mismatch»La URI del paso 10.4 no coincide letra por letra con TU_URL/api/google/callback. Corrígela en Google Cloud (tarda unos minutos en aplicarse).
Google: «Acceso bloqueado: app no completó la verificación»Tu correo no está como usuario de prueba (paso 10.3, punto 4).
«Google no entregó el permiso permanente»Quita BiBuru en https://myaccount.google.com/permissions y vuelve a conectar.
YouTube dejó de sincronizar tras una semanaLa app seguía en modo «pruebas»: haz el paso 10.6 y reconecta.
El importador de PROFITY falla al conectarCadena de Neon incorrecta o con comillas. Debe ir sin comillas y completa (incluye ?sslmode=require si Neon la da así).
Veo la pantalla «sin conexión» con internetCierra y vuelve a abrir la app. Si persiste, en Safari: Ajustes → Safari → Avanzado → Datos de sitios web → borra el de tu dominio y vuelve a instalar.
