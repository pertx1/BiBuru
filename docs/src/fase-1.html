BiBuru · Fase 1

Guía paso a paso para dejar la base funcionando en tu ordenador y en tu iPhone. Tiempo estimado: 45–60 minutos. Coste: 0 €.
Cómo leer esta guía. Cada paso dice dónde entrar, qué pulsar, qué copiar y dónde pegarlo. Lo que va en este formato es un botón o menú que ves en pantalla. Lo que va en este otro es texto que copias o escribes tal cual. Las páginas web cambian de diseño de vez en cuando: si un botón se llama algo parecido pero no idéntico, es ese. Si algo no coincide en absoluto, hazme una captura y dime en qué paso estás.

0 · Antes de empezar

Necesitas:

  • Un ordenador con Chrome (o el navegador que uses).
  • Tu iPhone con Safari (iOS 16.4 o superior; para las notificaciones de la Fase 5).
  • Acceso a tu correo oiier.gsss@gmail.com (recibirás códigos de acceso).
  • Tu cuenta de GitHub (usuario pertx1).
  • Un bloc de notas (o la app Notas) para ir pegando datos que vas a necesitar. Lo llamaremos «mi bloc».
Nada de esto pide tarjeta. Supabase, Vercel y GitHub tienen planes gratuitos sin tarjeta. Si alguna pantalla te pide una tarjeta o te ofrece «Upgrade», pulsa Cancelar / Skip / Continue with Hobby y avísame.
Regla de oro de seguridad. Hay claves que se pueden pegar sin miedo en Vercel (las que te digo aquí) y claves que no se comparten con nadie, ni conmigo: la contraseña de la base de datos y la clave service_role / secret de Supabase. En esta fase no necesitas pegar ninguna de las dos en ningún sitio.

1 · Llevar el código a la rama principal de GitHub

Ahora mismo el código está en una rama de trabajo. Vercel despliega desde la rama main, así que hay que fusionarlas.

  1. Dime en el chat: «crea la PR de la Fase 1». Yo abro una Pull Request (una propuesta de fusión) y te doy el enlace.
  2. Abre el enlace. Entra en GitHub (si te lo pide).
  3. Baja hasta el recuadro verde/gris y pulsa Merge pull request.
  4. Pulsa Confirm merge.
  5. Comprueba: entra en https://github.com/pertx1/BiBuru y verás carpetas como src, supabase, docs. Si la pestaña Actions muestra un círculo naranja o un ✔ verde, es la comprobación automática; si sale una ✘ roja, dímelo.

2 · Crear tu base de datos en Supabase

2.1 Crear la cuenta

  1. Entra en https://supabase.com y pulsa Start your project (arriba a la derecha).
  2. Pulsa Continue with GitHub y autoriza. Así no necesitas otra contraseña.
  3. Si te pide crear una Organization: nombre Personal, tipo Personal, plan Free. Pulsa Create organization.

2.2 Crear el proyecto

  1. Pulsa New project.
  2. Name: biburu.
  3. Database Password: pulsa Generate a password. Cópiala a «mi bloc» bajo el título «Contraseña BD Supabase». No la necesitarás ahora, pero si la pierdes se puede restablecer.
  4. Region: elige West EU (Ireland) o Central EU (Frankfurt). Cualquiera de Europa; más cerca = más rápido.
  5. Si aparece un Pricing plan / Compute, deja Free (0 $/mes).
  6. Pulsa Create new project y espera 1–2 minutos hasta que desaparezca la rueda de carga.
Dato: los proyectos gratuitos de Supabase se pausan si pasan 7 días sin ningún uso. Con el uso diario de la app (y el cron de la Fase 5) no ocurrirá. Si algún día ves «Project paused», entra y pulsa Restore project.

2.3 Copiar la URL y la clave pública

  1. En el menú izquierdo, abajo del todo, pulsa el engranaje Project Settings.
  2. Pulsa API Keys (en algunas versiones: API o Data API).
  3. Busca la Project URL (algo como https://abcdefghijk.supabase.co). Cópiala a «mi bloc» como SUPABASE_URL. Si no la ves en esa pantalla, está en Project Settings → Data API o en General.
  4. En API Keys busca la clave Publishable key (empieza por sb_publishable_…). Pulsa el icono de copiar y pégala en «mi bloc» como PUBLISHABLE_KEY.
    Si tu pantalla solo muestra la pestaña Legacy API Keys, copia la clave anon / public (empieza por eyJ…) y anótala como ANON_KEY. También sirve.
NO copies la clave llamada secret (sb_secret_…) ni service_role. Son las llaves maestras. No las necesitas ahora.

3 · Crear las tablas (aplicar la migración)

La «migración» es un archivo con instrucciones SQL que crea las tablas de usuarios, espacios y perfiles con sus reglas de seguridad.

  1. En GitHub abre https://github.com/pertx1/BiBuru/blob/main/supabase/migrations/20261005000001_base.sql.
  2. Pulsa el icono de Copy raw file (dos cuadraditos, arriba a la derecha del código). Ya tienes todo el contenido copiado.
  3. En Supabase, menú izquierdo: SQL Editor.
  4. Pulsa + New query (o New SQL snippet).
  5. Pega (Ctrl+V / Cmd+V) en el recuadro grande.
  6. Pulsa el botón verde Run (o Ctrl/Cmd + Enter).
  7. Abajo debe poner «Success. No rows returned». Si sale un error rojo, haz captura y mándamela; no lo repitas más de una vez.
  8. Comprueba: menú izquierdo Table Editor. Deben aparecer profiles, workspaces y workspace_members.
No lo ejecutes dos veces. Si lo repites dará error («already exists»). Es inofensivo, pero no hace falta.

4 · Configurar el acceso por correo

4.1 Cerrar el registro público

  1. Authentication (icono de persona/candado, menú izquierdo).
  2. En el submenú, pulsa Sign In / Providers (puede llamarse Providers o Settings).
  3. Busca Allow new users to sign up (en algunas versiones está en User Signups) y apágalo.
  4. En Email, asegúrate de que está activado (Enable Email provider ON) y Confirm email ON. Si ves Email OTP Length, déjalo en 6.
  5. Pulsa Save.

4.2 Poner el correo bonito (con enlace y código)

  1. Authentication → Email Templates (puede estar dentro de Emails).
  2. Elige la plantilla Magic Link.
  3. Subject: borra lo que haya y escribe Tu acceso a BiBuru.
  4. Message body (modo Source): borra todo y pega el contenido del archivo supabase/templates/magic-link.html del repositorio (en GitHub ábrelo y pulsa Copy raw file).
  5. Pulsa Save.
¿Por qué un código además del enlace? En el iPhone, la app instalada y Safari son «mundos separados». Si pulsas el enlace del correo se abre Safari, no la app. Con el código de 6 dígitos entras directamente dentro de la app instalada.

4.3 Crear tu usuario

Como el registro está cerrado, tu usuario lo creas tú a mano una sola vez.

  1. Authentication → Users.
  2. Pulsa Add user → Create new user.
  3. Email: oiier.gsss@gmail.com.
  4. Password: escribe cualquier cosa larga y aleatoria (no la usarás nunca; entras con códigos). No hace falta guardarla.
  5. Marca la casilla Auto Confirm User.
  6. Pulsa Create user.
  7. Comprueba: Table Editor → profiles debe tener 1 fila, y workspaces otra llamada «Personal». Si están vacías, avísame (significa que la migración no se ejecutó entera).

5 · Publicar la web en Vercel

5.1 Cuenta

  1. Entra en https://vercel.com/signup.
  2. Elige Hobby (gratis, uso personal). Pon tu nombre.
  3. Pulsa Continue with GitHub y autoriza.

5.2 Importar el proyecto

  1. Pulsa Add New… → Project.
  2. En Import Git Repository, si no ves BiBuru, pulsa Adjust GitHub App Permissions y da acceso al repositorio BiBuru (Only select repositories → BiBuru → Save). Vuelve a Vercel.
  3. Junto a pertx1/BiBuru pulsa Import.
  4. Framework Preset debe decir Next.js. No toques el resto (Root Directory vacío, Build Command por defecto).

5.3 Variables de entorno (lo más importante)

Despliega el apartado Environment Variables y añade estas tres, una a una (nombre en Key, valor en Value, pulsa Add):

Key (nombre exacto)Value (qué pegar)
NEXT_PUBLIC_SUPABASE_URLLa SUPABASE_URL de «mi bloc» (https://….supabase.co), sin barra final.
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEYLa PUBLISHABLE_KEY (sb_publishable_…). Si solo tienes la antigua, usa en su lugar el nombre NEXT_PUBLIC_SUPABASE_ANON_KEY con la clave eyJ….
ALLOWED_EMAILSoiier.gsss@gmail.com
Cuidado con espacios al principio o al final al pegar, y con errores en el nombre (mayúsculas y guiones bajos exactos). El 90 % de los fallos vienen de aquí.
  1. Pulsa Deploy. Espera 1–3 minutos. Saldrá confeti y «Congratulations!».
  2. Pulsa en la miniatura o en Continue to Dashboard. Verás tu dirección bajo Domains, parecida a biburu-xxxx.vercel.app. Cópiala a «mi bloc» como TU_URL (con https://).

5.4 Decirle a Supabase cuál es tu dirección

  1. Supabase → Authentication → URL Configuration.
  2. Site URL: pega TU_URL (por ejemplo https://biburu-xxxx.vercel.app), sin barra final.
  3. Redirect URLs → Add URL: pega https://biburu-xxxx.vercel.app/** (tu URL con /** al final).
  4. Pulsa Save changes.
Importante: el botón del correo usa la «Site URL». Si la dejas en localhost el enlace no funcionará.

6 · Probar en el ordenador

  1. Abre TU_URL en Chrome. Debe aparecer la pantalla de BiBuru con un recuadro de correo.
  2. Escribe oiier.gsss@gmail.com y pulsa Enviarme el acceso.
  3. Abre tu correo (mira también Spam). Llega «Tu acceso a BiBuru» en menos de un minuto.
  4. Pulsa Entrar en BiBuru (o escribe el código de 6 dígitos en la web).
  5. Debes ver «Hola, oiier.gsss» y el panel con la barra lateral a la izquierda.

Checklist del ordenador:

  • La barra lateral muestra Inicio, Tareas, Calendario, Negocios, Objetivos, Notas, Favoritos, Ajustes.
  • Al pulsar cada sección aparece una pantalla con un texto explicando qué llegará.
  • Ajustes: muestra tu correo, zona horaria Europe/Madrid y presupuesto de IA 10,00 €.
  • En Ajustes, el selector Claro / Oscuro / Sistema cambia el aspecto.
  • Pulsa Cerrar sesión: vuelves a la pantalla de acceso. Vuelve a entrar.
  • Prueba de seguridad: abre una ventana de incógnito, pega TU_URL: debe llevarte a la pantalla de acceso, sin mostrar nada. Intenta entrar con otro correo (p. ej. uno inventado): dirá que enviaste algo, pero no llegará nada y no podrás entrar. Es el comportamiento correcto.
  • Instalar en Chrome: a la derecha de la barra de direcciones aparece un icono de instalar (monitor con flecha). Púlsalo → Instalar. Se abre como una app.

7 · Probar en el iPhone

Tiene que ser Safari. Chrome para iPhone no puede instalar apps en la pantalla de inicio.
  1. Abre Safari en el iPhone y entra en TU_URL.
  2. Pulsa el botón Compartir (cuadrado con una flecha hacia arriba, en la barra inferior; en iPad arriba).
  3. Desliza hacia abajo en el menú y pulsa Añadir a pantalla de inicio (a veces dentro de Más).
  4. Deja el nombre BiBuru y pulsa Añadir (arriba a la derecha).
  5. Cierra Safari y abre BiBuru desde el icono nuevo de la pantalla de inicio. Debe abrir a pantalla completa, sin barra de direcciones.
  6. Escribe oiier.gsss@gmail.com → Enviarme el acceso.
  7. Sin cerrar BiBuru, ve a la app Mail (o Gmail) y abre el correo. Mira el código de 6 dígitos y apréndelo o cópialo. No pulses el botón del correo: abriría Safari, no la app.
  8. Vuelve a BiBuru (la app seguirá donde la dejaste), escribe el código y pulsa Entrar.
Si al volver a BiBuru la pantalla se ha reiniciado, no pasa nada: pide otro correo y usa el nuevo código (el anterior queda invalidado).

Checklist del iPhone:

  • Pantalla completa, sin barras de Safari. El contenido no queda tapado por la «isla» / muesca ni por la barra inferior del iPhone.
  • Barra inferior con Inicio, Tareas, botón + central, Negocios, Más. Todos los botones se pulsan sin esfuerzo.
  • El botón + central abre «La captura llega en la Fase 4».
  • Más lista Calendario, Objetivos, Notas, Favoritos y Ajustes.
  • Al tocar el campo de correo o código, la pantalla no hace zoom.
  • En Ajustes → Instalar la app pone «La app está instalada en este dispositivo ✔».
  • Cierra del todo la app (desliza hacia arriba desde abajo, quita BiBuru) y ábrela otra vez: sigues dentro, sin volver a pedir correo.
  • Modo avión: activa el modo avión, abre BiBuru y navega a otra sección: aparece «Sin conexión» (en Fase 8 se mejorará para leer lo último visto). Desactiva el modo avión.
  • Modo oscuro: Ajustes del iPhone → Pantalla → Oscuro; BiBuru se adapta si está en «Sistema».

8 · Si algo falla

SíntomaCausa probable y solución
El correo no llegaMira Spam. El correo gratuito de Supabase tiene un límite muy bajo (unos 2–4 correos por hora): espera 15–60 minutos. Comprueba que el correo está bien escrito y que creaste el usuario (paso 4.3). Supabase solo envía desde su servidor gratuito a direcciones del equipo de tu proyecto; como tú eres el dueño, el tuyo vale. Si insiste en fallar, dime y configuramos un SMTP gratuito (Resend).
«Código incorrecto o caducado»Cada correo nuevo invalida el anterior. Usa siempre el último. Escribe solo los números.
El enlace del correo abre una página de error o localhostLa Site URL no está bien (paso 5.4). Corrígela y pide otro correo.
Pantalla de error al abrir la web, o «Invalid input / Invalid URL»Falta o está mal escrita una variable de entorno (paso 5.3). Corrígela en Vercel → tu proyecto → Settings → Environment Variables y luego Deployments → los tres puntos del último → Redeploy. Las variables nuevas solo se aplican en un despliegue nuevo.
Entras pero vuelve a la pantalla de acceso una y otra vezALLOWED_EMAILS no contiene exactamente el correo con el que entras, o está vacía. Corrígela y redespliega.
«Hola» sin nombre en Inicio y Ajustes con valores por defectoTu fila de profiles no existe: el usuario se creó antes de ejecutar la migración. Dime y lo arreglamos con una línea de SQL.
En el iPhone no aparece «Añadir a pantalla de inicio»No estás en Safari, o estás en una pestaña privada. Abre Safari normal.
Vercel no encuentra el repositorioPaso 5.2: da permiso al repo en la app de GitHub de Vercel.
